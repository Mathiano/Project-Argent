# Vision gap audit — verified against the code (2026-09-23)

**What this is.** Every P0/P1 vision feature from `project-argent-scope.md`, `feature-ambition-scope.md` and the combat-enrichment roadmap, classified **from the code** (not from roadmap status lines — three of those proved months stale this month) as built / partial / not-built, then handed to an independent skeptic told to *refute* each claim. A completeness critic then read the vision docs for features the list missed.

**Why it exists.** The costly failure in this repo has been planning off a stale status line: re-proposing shipped work, or treating a one-row table entry as a buildable spec. This doc is the corrective. **Its most important column is "open rulings"** — the decisions a human has to make before the feature can be built without inventing design numbers (CLAUDE.md: never silently invent or change them).

**Method.** 8 classifier agents (3 features each) → 8 adversarial verifiers → 1 completeness critic. 17 agents, ~575 tool calls. Of 24 audited statuses, the skeptics disputed **none**; they sharpened several (noted inline). Full per-feature evidence (file:line) is in the workflow journal, not reproduced here.

## Headline

- **Built, confirmed:** intent tiers (honest / ambiguous / opaque), instant boss retry, the Calls toolkit.
- **Almost nothing unbuilt is design-locked.** Of the 21 partial/not-built features, the verifiers judged **zero** buildable without a human ruling. Most are one table row in a scope doc. The work that remains is mostly *decisions*, not code.
- **Three live doc-vs-code conflicts** surfaced (flagged, not resolved — see the bottom section).

## Per feature — what exists, what is missing, what must be decided

### `intent-tiers` — built

**Spec:** docs/intent-tells-design-note.md

**Exists:** The P0 three-tier ramp is built as the Phase 6.7-A plain-language text model. HONEST shows the exact stance, AMBIGUOUS shows an honest narrow-to-2 hint, and OPAQUE shows a blank dash. Resolution always confirms the true stance, so the tiers can be learned. Tiers are set per encounter from the trainer profile's infoLevel (with a per-axis override hook). Falkner is AMBIGUOUS, and wild and route trainers are HONEST. The same level also grades the Focus tell. At bond stage 4+ your partner raises clarity by one tier. The feature is presentation-only, and a test proves the engine is untouched.

**Missing:** (1) Nothing shipped uses the OPAQUE stance tier yet, because there is no Elite Four or Champion content. The veiled mid/elite profiles exist as dormant data. (2) There is no player-selectable Normal/Hard/Champion difficulty mode. The design note maps the tiers to progression instead, so this is a scope-wording question, not a bug. (3) The Phase 8 sprite-animation tells (the body-language vocabulary) are not built. (4) A banked playtest issue: the vague and opaque tiers don't tell the player that they are a different readability tier (docs/combat-backlog-banked.md:24). (5) The Call-intent seam is open but unbuilt: foeActionLine's 'call' case just says 'calls out'. Doc inconsistency to flag: the design note maps Gyms 1–4 to the honest tier, but the code makes Falkner AMBIGUOUS. This is a deliberate pull-forward per combat-depth-types-status.md Part 5 Issue A.

**Open rulings:** For the remaining (Phase 8) work: the tell animation vocabulary is marked 'sketch, not contract', and design must lock it before art is commissioned. The note's 'Reconcile at Phase 8' leaves open whether Champion tells withhold (current default) or lie. It is also open whether the scope's Normal/Hard/Champion means a player difficulty setting or the progression mapping, which encounters get OPAQUE, and how to make the vague and opaque tiers readable as tiers (the banked playtest finding).

**Skeptic's note:** The P0 ramp works end to end in the UI and has tests for HONEST and AMBIGUOUS. OPAQUE is only a tested code path with no live encounter, which the design note itself acknowledges ('The hook exists; late-game tuning is Phase 8'). The core mechanism is shipped, so 'built' is fair. The follow-up builder should know that opaque has no live content. The remaining Phase 8 animation-tell vocabulary is explicitly a sketch, so designLocked=false holds.

### `instant-retry` — built

**Spec:** docs/project-argent-scope.md (Prep Phase row 'Instant retry', line 57); docs/content-progression-scope.md:109 ('instant-retry-into-Prep makes losses cost ~30 seconds'); docs/falkner-boss-card.md:37,41 (the intended 'go catch a counter / train' answer)

**Exists:** Instant boss retry for the one shipped boss, Falkner. A loss heals the party in place, autosaves, and re-opens Falkner's scout-report prep sheet over the gym rooftop. There is no black-out and no walk back. Non-boss trainer and wild losses use the classic black-out (heal + warp to the last Center). There is a lose-path integration test through a mirrored harness. CLAUDE.md's claim (black-out + instant boss retry in main.ts) is accurate.

**Missing:** Polish and generalisation, not the core. (1) Prep has no exit, so after a loss the player cannot leave to catch or train the counter that the Falkner card names as the intended answer. Only a save reload gets them out. (2) There is no generic retry-into-Prep helper for future boss cards (Bugsy onward). (3) The dormant KAMON Route-32 gate has a Prep screen but blacks out to the Center on a loss. (4) The retry test drives a mirrored harness, not main.ts's actual handler.

**Open rulings:** Minor only. (a) Should Prep get a 'B: leave' back to the overworld, both on first entry and after a retry? falkner-boss-card.md implies yes, but no doc says so explicitly. (b) Is the KAMON Route-32 gate a 'boss' for the retry rule (retry into Prep) or a rival fight that keeps the black-out? The scope puts Prep before every rival fight.

**Skeptic's note:** Built for the one shipped boss. The core rule, from project-argent-scope.md:57 ('Boss loss drops you straight back into Prep, no walk of shame'), is fully specified, so designLocked=true for the core behaviour. The open items are small UX rulings: a Prep exit (implied by falkner-boss-card.md's 'go catch a counter' answer), and whether gate or rival fights count as bosses for the retry rule. A shared retry helper is a refactor, not a design question. Nobody should re-propose instant retry as new work. The follow-up is S-sized polish: a Prep 'B: leave' exit and generalising the retry for future boss cards.

Hang In There is retired from the UI per call-effects-design.md; its survive-at-1HP effect now lives on as the bond-moment.

**Missing:** No sanctioned Call is missing. What remains is banked/unsettled work plus doc drift. The code retired Hang In There from the UI (src/game/callEffects.test.ts:186-189; the engine branch at resolveRound.ts:150 is dormant), and Get Away grazes 25% (config.ts:112, recorded in docs/ui-and-calls-changelog.md §3 Fix 3). docs/bond-track-v2.md:26 carries the same stale list. docs/ui-and-calls-changelog.md §2 still says Shake It Off is LOCKED. (7) CLAUDE.md and bond-track-v2.md need updating to canonize the Get Away graze and Hang In There's retirement (or revert). (8) RESOLVE stays design-only pending the stage-7 bond design.

**Skeptic's note:** The built status holds, including the doc drift the audit flagged. ### `action-speed-timeline` — partial

**Spec:** docs/combat-2-0-spec.md §'Action timeline' (lines 91-93) + screen layout (line 13); docs/project-argent-scope.md row 'Action-speed turns' (line 36)

**Exists:** Engine: in-round action speed. Initiative = SPD / move-tier weight, so within a round a lighter move can let a slower mon act first. Fluid always acts first. A stagger halves the next round's initiative. Falkner's gust rounds add heavy-move init weight. Every round emits an 'initiative' event. The game shows turn order only implicitly, by playing the faster strike first as its own beat, plus a STAG chip. A pure orderHint() helper exists and is tested against the engine, but nothing renders it any more.

**Missing:** (1) No visible timeline strip. The spec's 'NEXT▸ [YOU][FOE][YOU][FOE]' face-chip strip was never built (the event handler is a stub), and the one-line NEXT: preview was built and then deliberately removed by the owner. (2) No cross-round action speed. Turns are simultaneous-commit rounds, so a heavy move acts later only within its own round. It does not delay your next act, and a light move does not bring you back sooner. (3) The nuke tier's delayNext flag is declared but never read, and no nuke-tier move exists. This conflicts with the CLAUDE.md canon line 'NUKE also delayNext — it delays the user's following action'. Per the docs-win rule it should be flagged, not silently changed.

**Open rulings:** (a) Does the P0 'visible timeline' override the owner's 067c3a6 declutter, which removed the turn-order readout as 'academy material', and is a test-pinned decision? (b) Should action speed carry across rounds (CTB-style: heavy delays the next act), or stay in-round initiative plus stagger only? Carrying it across rounds would restructure the simultaneous-commit round and the Focus two-step, and a 4–5-action look-ahead has no engine model today. (c) delayNext semantics and magnitude for NUKE: canon asserts it but gives no number. (d) Where the strip fits in the 640×360 battle-UI layout budget. (e) How this relates to the banked, not-yet-designed 'initiative as a read' idea (docs/combat-initiative-modifier-BACKLOG.md), whose hard constraint is 'extend, don't replace' the Layer 1 speed model.

**Skeptic's note:** Engine in-round initiative is built and tested, and resolveRound.ts:1037-1061 emits the 'initiative' event. Two things the spec calls for are missing: the visible NEXT strip (combat-2-0-spec.md:13 and :91-93) and cross-round delay, where a heavy move delays your next act (project-argent-scope.md:36). The spec text gives no delay magnitudes and no look-ahead model, so a builder would have to make the rulings. designLocked=false is correct. Keeping the audit's flag: the CLAUDE.md canon line 'NUKE delayNext delays the user's following action' has no consumer, and no nuke-tier move exists.

**Skeptic's note:** The audit is accurate. ### `field-state` — partial

**Spec:** docs/project-argent-scope.md:44 (plus docs/combat-2-0-spec.md §Arenas, docs/content-progression-scope.md:83, docs/combat-environments-AS-BUILT.md, docs/visual-north-star.md:58)

**Exists:** The TERRAIN third exists as Combat Layer 3 environments. There are seven data-driven biomes that tilt stance damage, release damage and flat per-round stamina. There's a meta-read nudge for trainers who claim the terrain. The layer is sim-gated for no dominant strategy, wired per map (Route 31 = forest) and announced in the battle intro. Falkner's scheduled gust rhythm is a fixed arena modifier.

**Missing:** The missing part is everything that makes it FIELD STATE rather than static ground. There is no weather system: no rain/sun/etc. that moves can set, change or contest turn by turn. There are no hazards: no entry or switch-in hazards and no side conditions. There is no interaction or chaining between field elements, such as Fire burning webs or Electric chaining off water. There are no moves or Calls that alter the field, and no mutable arena features (the Whitney/Bugsy/Morty/Clair hooks). The field can't change mid-battle at all. There's no per-encounter-zone ground. There's no field-state UI or art: no weather particle and palette layers and no arena backgrounds per environment. Trainer AI has no field-aware play beyond the static terrain lean, and no profile in CH1 claims a terrain.

**Open rulings:** (1) Is field state a new mutable layer, or an extension of Layer-3 environments? A contested field would break environment.ts's leak cap ('no new per-turn resource, no new number to track'). (2) Which weathers and hazards exist, what are their numbers and durations, and how does each interact with the stance/focus triangle? (3) The chaining and interaction rules: which types or moves alter which field elements. (4) How is the field contested ('every turn' for Misty), and what does it cost? (5) Which bosses and arenas get field features, and are they boss-card re-baselines? The AS-BUILT already flags the Falkner-on-cliff re-baseline and the environment-table re-derivation as open rulings for Mathias. (6) Scheduling: the docs defer this to Phase 8 / Kanto (Misty).

**Skeptic's note:** Layer-3 static environments are the only built third of field state. Weather, hazards, mutable arenas and chaining don't exist in the engine or the game. No doc carries numbers, durations or interaction rules, so designLocked=false holds. It's partial only in that the terrain layer exists. The weather and hazard parts are effectively not-built.
